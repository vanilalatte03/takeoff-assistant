# 안내형 산출 작업

기본 화면의 **작업 시작·이어서 하기**에서 한 PDF의 준비, 로컬 검색, 계산 초안, 원본 검토와 Excel 다운로드를 이어간다. 새 PDF 업로드도 이 화면으로 돌아온다. AI 설정이나 외부 모델 호출이 필요하지 않다.

1. 프로젝트를 선택하거나 만들고 PDF를 업로드한다. 기존 PDF는 이름으로 선택한다.
2. **도면 준비 시작·이어서 진행**을 누른다. 페이지 처리 → 감지 → 분류 → 마감 후보 추출 → 산출 후보 생성의 완료·대기·실패 상태를 확인한다. 실패 원인을 확인하고 같은 버튼으로 남은 단계부터 재시도한다.
3. 실 번호, 마감 코드, 원하는 항목을 입력해 **근거 찾기·다시 찾기**를 누른다. 검색 근거의 접힌 항목을 열어 원본 이미지를 본다. 해당 산출 행과 치수별 출처·후보 또는 수동값·확인 단위·메모를 입력하고 공제·면 수를 대조한 뒤 **계산하고 미확정 초안 저장**을 누른다.
4. **아래 원본 검토·Excel로 이동**을 누른다. 저장된 입력과 원본을 대조하고 검토 체크 후 **Excel 다운로드**를 누른다. 모든 행이 포함되므로 Details와 Review에서 미계산·미확정 행도 확인한다. 이 체크는 CONFIRMED 변경이 아니다.

페이지를 다시 열면 서버의 준비 완료 지점과 저장된 산출 행을 읽는다. 검색 요청·미저장 입력·검토 체크는 복원하지 않는다. 저장 행을 고르면 기존 원본 대조와 수동 계산 폼을 사용할 수 있다. 확정은 직접 계산 폼에서 명시적으로 선택할 때만 적용된다.

자동 마감/산출 후보가 0개이면 준비가 끝나도 준비 가능 상태로 표시하지 않는다. 화면의 **도면 분류 확인 → 마감 후보 직접 입력·수정 → 산출 후보 생성** 경로를 이용한 뒤 **후보 다시 불러오기**로 돌아온다. 원본 이미지가 없거나 잘못된 분류는 도면 목록/상세에서 확인한다. 저장 근거 조회 실패는 **원본 근거 다시 불러오기**, 요청 실패는 입력 수정 후 **근거 찾기·다시 찾기**, Excel 실패는 같은 다운로드 버튼으로 재시도한다.

## 재실행과 보존 계약

- `GET /drawing-files/{id}/workflow`는 준비 상태와 현재 후보 수를 읽는다. `POST .../workflow/prepare`는 다음 한 단계를 실행한다. 화면이 이를 순서대로 이어 호출한다.
- `drawing_preparations` 테이블을 `create_all`로 추가한다. 기존 테이블·행을 삭제하거나 초기화하지 않는다. 완료 단계, 새로 만든 시트 ID, 경고만 저장한다. 기존 DB 사용 전에는 평소처럼 백업한다.
- 새 PDF 페이지 처리 중 실패하면 해당 단계의 DB 변경을 rollback하고 이전 완료 단계는 유지한다. 일부 렌더링 파일은 재시도에서 같은 원본으로 재생성한다. 완료한 단계는 건너뛴다.
- 준비 기록 없이 기존 시트가 있으면 원문·번호·제목·역할·검수 상태를 그대로 채택하고 처리/감지/분류를 건너뛴다는 경고를 표시한다. 사용자의 빈 메타데이터나 UNKNOWN도 의도적 수정일 수 있어 추정 덮어쓰기를 하지 않는다. 새로 생성한 시트도 중간에 번호/제목/역할 또는 확정·제외 상태가 바뀌면 해당 자동 덮어쓰기를 건너뛴다.
- 마감 추출과 후보 생성은 기존 중복 방지 로직을 재사용한다. 수정한 마감·산출 행, 확정/제외 상태, 식·수량·단위·출처·좌표·공제 근거를 갱신하지 않는다.
- 지원하는 단일 로컬 API 프로세스에서 준비 요청을 잠근다. 겹친 요청은 409로 거부한다. 여러 API worker/서버를 같은 DB에 연결하는 운영은 지원 범위 밖이다. 기존 고급 개별 재처리 버튼은 이 보호된 준비 API와 다르므로 작업 안내에서 자동 호출하지 않는다.
- UI는 실행 중 버튼과 입력을 보호하고 즉시 중복 클릭을 막는다. PDF 전환 시 화면과 검색·검토 상태를 재생성하고 이전 응답·다운로드를 표시하지 않는다. 진행 중 서버 요청 한 건은 끝날 수 있지만 다음 단계는 이전 PDF에 계속 요청하지 않는다. 초기 상태 조회는 StrictMode의 오래된 응답도 무시한다.

## 개발 검증 (2026-11-06)

`test_guided_workflow.py`는 합성 PDF로 이미지/감지 실패와 재시도, 완료 단계 건너뛰기, 중복 요청 409, 기존 시트 수정과 확정·제외 산출 행의 전체 JSON 보존, 후보 0건을 검증한다. `workflow.test.tsx`는 정상 진행·계산 저장 연결·다운로드, 실패 재시도, 재개, 중복 클릭, PDF 전환 중 오래된 검색/준비 응답, StrictMode 역순 초기 응답을 검증한다. 이 컴포넌트 회귀에서 계산 저장은 대체 컴포넌트를 사용하며 실제 계산 검증은 API와 아래 브라우저 확인으로 구분한다.

실제 Chromium과 임시 SQLite·업로드·렌더·다운로드 폴더를 사용했다. 테스트 파일의 공개 합성 3쪽 PDF로 새 프로젝트 생성 → 업로드 → 준비 5단계 → `110호 ACST 천장 면적` 로컬 검색 → 마감표/평면도 원본 확인 → 4200/2700mm·공제 없음 사용자 확인 → `4.2 * 2.7 = 11.34 m2` DRAFT → 저장 원본 대조 → Excel 다운로드를 수행했다. 내려받은 workbook을 openpyxl로 열어 Summary/Details/Review, 식·수량·단위·출처 `ZX701, ZX201`·DRAFT를 확인했다. 나머지 9행의 수량은 비어 있다. 새로고침 시 준비/초안 재개를 확인했다. 두 번째 합성 PDF의 저장 원본을 임시로 다른 이름으로 옮겨 실제 404와 실패 단계 표시를 확인한 뒤, 원본을 복원하고 재시도로 5단계 완료를 확인했다. 첫 PDF/두 번째 PDF 전환에서 초안이 섞이지 않고 첫 PDF의 저장값이 재개되는 것도 확인했다. 브라우저 로그에는 초기 favicon 404와 의도한 원본 부재 404가 있었고 앱 JavaScript 예외는 없었다.

로컬 증거는 `output/playwright/step3-source-review.png`, `step3-complete.png`, `step3-workbook-verification.json`과 `.playwright-cli/`의 실제 명령별 스냅샷·다운로드다. 공개 저장소에는 업무 자료나 실행 DB를 추가하지 않는다. CLI 명령은 `npx.cmd --yes --package @playwright/cli playwright-cli -s=step3 open http://127.0.0.1:5173 --headed`, `snapshot`, `click`, `fill`, `select`, `upload`, `check`, `screenshot`을 사용했다.

이는 개발자가 합성 과제를 수행한 확인이다. 아버지/실무자가 문서 없이 완주했는지, 업무 도면의 정답·공제·면 수가 맞는지, AI 품질과 작업시간이 개선됐는지는 검증하지 않았다. phase step7과 R-04/11/12의 외부 게이트를 유지한다.
