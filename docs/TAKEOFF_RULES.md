# 산출 규칙 카탈로그와 기준 사례

이 문서는 현재 계산 계약과 검수 질문을 정리한다. 실제 현장의 정답 규칙을 확정하는 문서가 아니다. 프로젝트 도면·시방서·계약 기준을 우선하며, 검수하지 않은 자동 결과는 DRAFT 또는 NEEDS_REVIEW로 유지한다.

| 산출 유형 | 필수 입력 | 계산 | 단위 | 검수 질문 |
| --- | --- | --- | --- | --- |
| 바닥·천장 | 가로, 세로 또는 사용자가 측정한 면적 | 기준 면적 − 면적 공제 합 | m2 | 방 경계, 기둥·개구부·가구 등의 공제를 확인했는가? |
| 둘레·걸레받이 | 가로, 세로 또는 측정 길이 | 기준 둘레 − 길이 공제 합 | m | 출입구를 공제하는가? 측정 구간이 맞는가? |
| 벽 | 벽 길이, 적용 높이 | 길이 × 높이 − 면적 공제 합 | m2 | 높이가 해당 실에 적용되는가? 문·창문 공제를 확인했는가? |
| 파티션 | 벽 길이, 적용 높이, 산출 면 수 | 길이 × 높이 × 면 수 − 면적 공제 합 | m2 | 타입·재료·면 수·공제 기준을 확인했는가? |
| 개수 | 사용자 확인 개수 | 개수 | EA | 중복 클릭·누락·대상 종류를 확인했는가? |

모든 결과는 계산식·수량·단위·출처·상태를 저장한다. 도면 측정 좌표는 coordinates_json, 공제는 deductions_json에 남긴다. 기존 계산 엔진은 Decimal로 계산하고 소수 둘째 자리로 반올림한다. 파티션 엔진의 기본 면 수 1은 기술적 기본값이며, AI가 현장 적용 면 수로 간주해서는 안 된다. AI 계산 도구에서는 면 수를 명시적으로 확인해야 한다.

## 합성 기준 사례

| ID | 과제 | 확인한 입력과 가정 | 예상 결과 |
| --- | --- | --- | --- |
| E-01 | 110호 ACST 천장 | 가로 4.2m, 세로 2.7m, 공제 없음 | 11.34m2 |
| E-02 | 119호 5A 파티션 | 길이 4.2m, 높이 4.6m, 면 수 1, 공제 없음 | 19.32m2 |

`apps/api/tests/test_known_takeoff_workflow.py`는 고객 도면 없이 합성 PDF를 만들고 실제 API로 업로드·페이지 처리·역할 분류·마감표 추출·후보 생성·수동 코드 수정·계산·사용자 확정·Excel 출력을 검증한다. ZX701/ZX201/ZX501은 테스트 식별자이며 제품 규칙이 아니다. 치수는 검증자가 입력한 값으로, 자동 치수 해석 정확도를 증명하지 않는다.

자동 재생성은 수정된 코드의 기존 후보를 중복 생성하지 않아야 한다. CONFIRMED/REJECTED 행의 재계산은 409로 거부한다. 확정 행만 명시적으로 DRAFT로 변경해 재검토할 수 있다. 제외 행은 복구하거나 수정할 수 없다.

## 데이터셋과 평가

기존 4차 Excel 데이터셋 검증기는 형식·허용 값·필수 값·JSON·private 경로를 검사한다. 산출 규칙의 정확성이나 도면 근거의 진위를 검증하지 않는다. 20~50건은 실제 사용자가 검수한 사례의 장기 목표이며, 합성 두 건으로 대체하거나 완료 처리하지 않는다.

정상 산출 데이터와 치수 누락·단위 불명·다중 시트·상충 치수 같은 실패 평가 사례는 구분한다. 실패 사례는 수량이 없을 수 있으므로 수량 필수인 정상 데이터셋에 억지로 채우지 않는다. E-03~E-06의 AI 도구 검증은 AI 단계에서 추가한다.

단위 추정과 실제 단위 확인은 다르다. 현재 치수 후보의 unit_guess와 normalized_value는 휴리스틱이므로, AI는 사용자 또는 도면의 명시 단위 근거 없이 계산 입력으로 확정하지 않는다.
