# 로컬 파일럿 관찰·비교 절차 (6차 step6 준비)

현재 실제 파일럿은 **미실행, 0건**이다. 이 문서와 도구는 관찰 준비이며 실무 정확도·시간 절감 증거가 아니다. 기존 합성 검색·Vision 평가 및 실모델 5회/2819토큰은 작업시간·채택 증거로 재사용하지 않는다. step7과 R-04/11/12는 blocked를 유지한다.

## 먼저 한 과제 관찰

1. 실무자 참여와 기존 도면의 로컬 이용 권한을 확인한다. 사용자 DB와 업로드를 백업하고, 공개 발표·외부 공유 범위를 정한다. 키나 업무 PDF/DB를 Git에 넣지 않는다. 로컬 파일럿에 외부 전송 승인은 필요하지 않지만 AI/Vision으로 업무 자료/crop을 전송하려면 별도 명시 승인이 필요하다. 승인 전에는 manual/local만 사용한다.
2. 실무자와 작은 천장 과제 하나를 고른다. 예: 하나의 실에서 지정 천장 마감의 면적을 찾고 원본 치수·단위·공제 기준을 대조하여 Excel Details의 식·수량·단위·출처를 검수한다. 도면 번호를 고정하지 않는다. 이 탐색 관찰은 본 비교와 다른 묶음 ID, 연습으로 기록한다. 정상 수량을 미리 지어 넣지 않는다.
3. 참여자는 화면 안내대로 업로드→준비→근거 탐색→초안→원본 대조→수정→Excel 확인을 진행한다. 관찰자는 시작/종료와 막힌 위치, 잘못 선택한 근거, 요청한 도움, 오류 메시지와 재시도를 기록한다. 도움을 주었다면 수동 개입 횟수·내용을 남긴다. 채택하지 않거나 완료하지 못해도 기록한다.
4. 막힘마다 재현·기대 동작·실제 동작·영향을 기록하고 별도 결함 PR로 고친다. 완료/채택을 유도하기 위해 기록을 덮어쓰지 않는다. 수정 후 앱 revision을 바꾸고 새 묶음으로 본 비교한다.

## 첫 1과제 관찰 양식

아래 빈칸을 실제 관찰로 채운다. 참여자/관찰자는 가명 식별자를 권장한다. 화면의 `실사용 비교 기록 → 파일럿 관찰 상세`에서 입력하며, 기존 간단 기록도 계속 가능하지만 시간 비교에는 포함하지 않는다.

| --- | --- |
| 비교 묶음 / 과제명 / 분류 | ___ / ___ / 천장 등 |
| 참여자 / 관찰자 / 관찰 일시(시간대) | ___ / ___ / ___ |

준비 소요시간은 시간 포함 여부와 별도로 기록한다. 포함이면 총 초에 이미 포함된 값이며 다시 더하지 않는다. 제외이면 총 초 외의 비용이다. 서로 다른 준비 정책/캐시/앱 revision/설정은 같은 비교 조건으로 취급하지 않는다. 분석은 포함 정책이면 전체=원기록, 과제=원기록−준비, 제외 정책이면 전체=원기록+준비, 과제=원기록으로 구분한다. 포함 준비가 원기록보다 크면 저장을 거부하고 과거 모순 기록도 시간 비교에서 제외한다. 과제 시간차만으로 전체 시간 절감을 주장하지 않는다. 화면의 참여자·관찰자·조건은 다음 기록에 유지되지만 관찰 일시와 완료·시간 범위 확인은 저장 후 초기화된다. 각 시도마다 내용과 순번을 다시 확인한다.

## 본 비교 설계와 분석

첫 관찰의 결함 해결 후 동등한 과제 묶음을 고정한다. 같은 과제명/정의와 PDF fingerprint, 같은 참여자·묶음·조건·준비 정책·캐시에서 manual/local/ai를 기록한다. Vision을 평가할 때는 ai 대신 vision을 세 번째 방식으로 정하고 별도 묶음을 사용한다. 앱 기록 생성 시각이나 ID로 실제 실행 순서를 추정하지 않는다.

학습을 줄이기 위해 묶음별 순서를 manual→local→ai, local→ai→manual, ai→manual→local로 교대한다(vision도 같은 방식). 순서 교대가 학습 효과를 제거한다는 주장은 하지 않는다. 연습은 별도 묶음으로 분리한다. 방식별 시간이 짧아도 실패·중단·거절이면 절감으로 세지 않는다. 모든 시도와 재시도를 별도 저장하고 가장 빠른 것만 골라내지 않는다. 같은 묶음에 재시도가 있으면 전체 묶음을 시간 비교에서 제외한다. 새 재실행은 변경 조건·실패 원인·앞선 묶음 ID를 명시하고 새 묶음으로 남긴다.

`관찰 전체 JSON 내보내기·분석`은 로컬 브라우저 다운로드다. 서버/외부 업로드가 아니며 PDF 원문이나 키를 포함하지 않는다. 자유 메모는 업무 정보를 포함할 수 있으므로 JSON도 비공개로 보관한다. 기존 trial JSON에 optional `pilot.schema_version=1`을 저장하고 DB schema는 바꾸지 않는다. legacy는 수정·보충 추정하지 않는다.

- `GET /drawing-files/{id}/assist/trials/export`: 모든 원본 기록과 analysis. 최근 100건으로 자르지 않으며 실패·거절·재시도·legacy도 남긴다.
- `GET /drawing-files/{id}/assist/trials/analysis`: 같은 서비스의 분석만 반환한다. 관찰이 없으면 NOT_RUN, 0건, 비교 없음이다.
- `record_count`/`record_ids`: 전체 입력 분모. `excluded_count`/`excluded`: 시간 비교 제외 개수와 record ID·이유(여러 이유가 있을 수 있음).
- `common_completed_task_count`/`comparisons`: 동일 조건의 정확히 세 방식 각 1회가 관찰 완료·시간 범위 확인·완료·검수 채택된 묶음만. 원기록 초(recorded_elapsed_seconds), 준비 제외 과제 초(task_seconds_excluding_preparation), 준비 포함 전체 초(total_seconds_including_preparation), 각각 manual 빼기 보조 초(음수 허용), 수정·개입·오류·잘못된 근거 수와 준비 초를 제공한다. 개별 묶음만 기술하며 다른 조건/과제를 합산하지 않는다.
- 누락/잘못된 pilot, 연습, 미검수/거절, 관찰·시간 범위 미확인, 순서 불일치, 방식 누락/중복, 과제 정의·조건·파일 버전 불일치는 제외한다. 제외된 시도가 같은 묶음에 있으면 나머지도 제외한다.
- `mode_summaries`: real/synthetic/unknown을 분리한 방식별 전체 기록 수·유효 관찰 수·실패/중단 수·검수 상태 수. 실패율 분모는 해당 방식/출처의 **모든 유효 관찰 시도(연습·재시도 포함)**이며 미검수/거절 시도도 포함한다. 유효 관찰 0건이면 null. 조건별 성과나 정확도로 해석하지 않는다. `attempt_outcomes`와 전체 원본에서 ID별 실제 맥락을 확인한다.

관찰 기록은 user_reported다. 채택은 사용자의 판단이며 프로그램이 정답을 판정한 정확도가 아니다. 소표본 유의성·인과·전체 실무 정확도·보장된 시간 절감을 주장하지 않는다. 바닥/천장/파티션 등 서로 다른 과제와 실무자가 승인한 20~50건 정답의 검수·실제 비교·채택 판단은 step7 외부 게이트다.

## 개발 검증과 실무 미검증

`test_pilot_evaluation.py`, `comparison.test.tsx`의 시간과 관찰은 synthetic fixture이며 임시 테스트 DB/mock에만 존재한다. 업무 DB나 실사용 성과로 저장·발표하지 않는다. 모델 호출 없이 동일 조건 비교, 모든 시도 보존, 누락/불일치 제외, 기본 0건, JSON 다운로드를 검증한다. 전체 명령은 COMMANDS의 manual 검사다. 실제 참여자 관찰·업무 자료 검수·본 비교 결과는 아직 없다. 2026-11-09 사용자 확인으로 앱에 설정한 OpenAI Responses API를 통한 선택 영역 PNG 전송 범위는 허용으로 반영했다. 앱의 도면별 이용권한·전송 consent 확인은 유지하며 이 준비 단계에서는 실제 업무 파일 접근이나 추가 모델 호출을 수행하지 않는다. 실무자 참여 일정은 미정이다.
