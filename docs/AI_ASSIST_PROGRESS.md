# AI 보조 PRD 실행 기록

기준: 사용자가 제공한 `PRD_Takeoff_Assistant_AI_Assist_v0.1.md` (검토용 초안). 사용자 요청에 따라 기존 로컬 변경을 보존하면서 구현한다.

## 실행 순서

1. 합성 기준 사례와 API→Excel 통합 검증, 수동 산출 UX, 규칙 카탈로그.
2. 단일 AI 작업 패널, 프로젝트 범위가 제한된 읽기 전용 검색, 근거와 실행 기록.
3. 명시적으로 검증된 입력으로 계산 엔진 호출, 미확정 초안, 사용자 검수, E-01~E-06 평가.
4. 실제 실패 유형에 한정한 선택 영역 Vision 보완과 실사용 비교. 승인된 실제 도면·정답·사용자 검수가 필요하다.

## 현재 변경

- 합성 PDF 2개 예제의 업로드부터 Excel까지 통합 테스트 추가.
- 프로젝트별 업로드 PDF 목록 API와 이름 기반 공통 선택 UI 추가. 화면 이동 시 같은 탭에서 선택을 유지한다.
- PDF 변경 시 산출·마감·검색 화면을 다시 만들어 이전 도면의 결과가 남지 않게 한다.
- 확정·제외 행 재계산 차단과 명시적 DRAFT 재검토 버튼 추가.
- 수정한 마감 코드의 후보가 재생성으로 중복되는 문제 수정.
- 산출 규칙·가정·실무 검증과 합성 검증의 차이를 TAKEOFF_RULES.md에 정리.
- 산출 탐색 보조 화면 추가. 로컬 규칙 검색과 선택적 AI 도구 검색을 명확히 구분한다.
- AI 검색은 요청 문장만 외부 모델로 보내고, 모델이 반환한 검색 인자를 검증한 뒤 서버가 선택한 PDF 안에서만 검색한다. 원문 인용은 서버가 만들며 모델 자유 서술을 근거로 표시하지 않는다.
- 검색 실행 상태·도구 인자·근거·오류 분류·지연시간·가능한 토큰 사용량은 로컬 assist_runs 테이블에 보존한다. 최근 20회는 도면별 API로 조회할 수 있다.
- 탐색 결과에 마감 후보와 원문·좌표가 있는 치수 후보를 연결했다. 수치 크기에 의한 단위 추정은 표시만 하며, 계산에는 사용자 확인 단위를 요구한다.
- 계산 초안 폼과 `calculate_quantity`/`create_measurement_draft` 서버 도구를 추가했다. 사용자 확인 입력으로 기존 엔진을 호출하며 기존 산출 후보에 DRAFT로 저장한다. AI가 수량을 생성하거나 확정 상태를 지정할 수 없다.
- 파티션 면 수·공제 검수·입력별 출처·검수 메모를 요구하고, 다른 도면·실·코드의 근거 혼합과 오래된 탐색 결과를 거부한다. 재시도는 같은 행을 갱신하며 중복 행을 만들지 않는다.
- 원본 치수·확인 단위·단위 변환·선택 영역 좌표·공제·탐색 실행 ID를 산출 행에서 추적할 수 있다. 수동 확정·수정 결과도 실행 기록에 반영한다.
- `2.7m`를 `2`로 잘못 읽을 수 있는 치수 추출 문제와, REJECTED 행에 수량이 남아 있으면 Excel Summary 합계에 포함되는 문제를 수정했다. Details에는 제외 이력을 상태와 함께 남기며 Review·Summary에서 제외한다.

## 사용자 제공 설정으로 실제 호출 검증 (2026-11-05)

- 사용자가 알려준 외부 `.env`의 키와 `gpt-6.1-terra` 설정을 프로세스에서만 읽었다. 키를 출력·복사하지 않았고 원본 `.env`도 수정하지 않았다.
- 실제 모델을 연결한 합성 평가 E-01~E-06과 V-01 총 7항목이 최종 실행에서 통과했다. `AI_ASSIST_LIVE_RESULT.json`에 호출별 응답 식별자·토큰·시간을 기록했다. E-03~E-05는 실제 검색 결과 이후 서버의 누락 입력·다중 시트·단위 확인 계약을 검증하며, 모델 자체의 도면 이해 능력을 별도로 측정한 항목은 아니다.
- 최종 1회 평가에서 검색 호출 3건은 각각 2464/1685/2272ms, 합성 crop 판독 1건은 4376ms였고 총 1867토큰을 사용했다. 이는 단일 실행 관찰값이며 성능 보장이나 전체 작업의 누적 비용이 아니다.
- 최초 실행의 사례들은 통과했으나 Windows 임시 SQLite 정리에서 파일 잠금이 발생해 엔진 풀을 닫도록 수정했다. 반복 실행 중 HTTP 오류 1회도 관찰했으나 당시 상태 코드가 없어 원인은 확정하지 않았다. 이후 비밀 본문을 노출하지 않고 HTTP 상태·제공자 오류 코드만 실행 기록에 남기도록 보완했고 최종 실행이 통과했다.
- `run_api.py`로 외부 설정을 읽은 실제 서버의 ai_available/vision_available이 모두 true임을 확인했다. Vision 별도 모델이 없는 경우 명시적 옵션으로 같은 모델을 현재 프로세스에서만 사용한다.
- 전체 회귀 API 178개 + 스크립트 80개 = 258개와 웹 빌드 통과. 실제 호출 평가는 별도 유료 명령으로만 실행된다.

- 이번 항목은 문서 동기화와 실행 계획이다. 새로운 실무 정답, 실제 모델 품질 점수나 시간 절감 결과를 얻었다는 뜻이 아니다.
