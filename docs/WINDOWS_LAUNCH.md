# Windows에서 클릭으로 시작하고 종료하기

최초 1회는 [README 준비 명령](../README.md#빠른-시작--windows-powershell)으로 Python 3.11 가상환경과 API 의존성, Node.js 24와 웹 의존성을 설치해야 합니다. 설치 프로그램은 포함하지 않습니다. 이후에는 터미널에 명령을 입력할 필요가 없습니다.

현재 검증: 실제 Windows에서 시작 버튼·브라우저 진입과 비정상 종료 정리, 자동 테스트의 정상 종료·데이터 보존을 확인했습니다. 2026-11-08 사용자는 임시 데이터 확인 helper로 **시작 → 안전 종료 완료**, **다시 시작 → ×로 창 닫기**를 수행한 결과에 “두 동작 모두 정상”이라고 응답했습니다. 이는 사용자 관찰이며 CUA 실측과 구분합니다. step4는 completed입니다. [정책 중단 이력·사용자 확인과 검증 범위](../issues/6-usability-evaluation/issue-4.md)를 확인하세요.

## 일상 사용

1. 탐색기에서 저장소의 **Start Takeoff.cmd**를 더블클릭합니다. 짧게 준비 창이 나타난 뒤 **Takeoff Assistant 실행기**가 열립니다. Python이 없으면 준비 안내가 나타납니다. 실행 정책·보안 경고가 차단하면 이를 우회하지 말고 관리 담당자에게 확인합니다.
2. 보통 설정 없이 **시작**을 누릅니다. 필요할 때만 **외부 설정 파일 선택**에서 기존 UTF-8 `.env`를 선택합니다. **설정 파일 선택 해제**로 파일 없이 돌아갈 수 있습니다(기존 환경변수는 유지). 파일은 복사·수정하지 않으며, 기존 환경변수가 우선합니다. 키는 출력하거나 브라우저로 보내지 않습니다. 키가 없으면 AI를 호출하지 않고 로컬 기능을 사용합니다.
3. API와 웹 준비가 끝나면 기본 브라우저의 `http://127.0.0.1:5173/workflow`가 열립니다. 브라우저가 열리지 않으면 **작업 화면 열기**를 누르거나 표시된 주소를 사용합니다. API 8000 / 웹 5173 모두 **127.0.0.1**에만 바인딩합니다.
4. 작업 화면에서 저장 완료를 확인하고 **안전 종료**를 누릅니다. 실행기 창의 **×**도 같은 종료를 수행합니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.
5. **안전 종료 완료**를 확인합니다. 실행기는 계속 열려 있으므로 **시작**으로 다시 사용할 수 있습니다. 창을 닫으려면 ×를 누릅니다. 서버가 꺼진 뒤 브라우저 탭은 직접 닫습니다.

API는 Uvicorn 정상 종료를 요청해 진행 중인 요청을 기다립니다(서버 요청 대기 20초, 프로세스 대기 최대 25초). 응답하지 않으면 이번 실행의 서버만 강제 종료하고 마지막 저장 확인을 안내합니다. **종료 중**에는 저장·업로드를 새로 시작하지 마세요. 강제 종료 후에는 재실행해서 마지막 저장 항목을 원본과 대조합니다. 처리 중이던 작업의 성공은 보장하지 않습니다.

## 데이터 위치와 안전한 백업

기본 저장 위치는 아래와 같으며, **실행기에서 시작 시 표시한 실제 위치**를 확인합니다. 외부 설정 또는 기존 환경변수가 있으면 달라집니다. `TAKEOFF_DATA_DIR`만 바꿔도 나머지 경로가 자동으로 함께 바뀌지는 않습니다.

| 내용 | 기본 위치 | 외부 설정 |
| --- | --- | --- |
| SQLite DB | `data/takeoff_assistant.db` | `TAKEOFF_DATABASE_URL=sqlite:///...` |
| 원본 PDF | `data/uploads/` | `TAKEOFF_UPLOADS_DIR` |
| 렌더링 PNG | `data/rendered/` | `TAKEOFF_RENDERED_PAGES_DIR` |
| 생성한 Excel | `exports/` | `TAKEOFF_EXPORTS_DIR` |

1. 브라우저에서 저장 성공을 확인하고 실행기의 **안전 종료 완료**를 기다립니다. 별도 개발 터미널에서 같은 DB를 연 서버가 있다면 그 서버도 정상 종료합니다. **실행 중인 SQLite 파일을 단순 복사하지 않습니다.** 강제 종료가 있었다면 앱을 다시 열어 저장 상태를 확인한 뒤 정상 종료하고 백업합니다.
2. 탐색기에서 새 날짜의 **빈 백업 폴더**를 만듭니다. 위 실제 위치의 DB 파일과, 같은 이름의 `-wal`, `-shm`, `-journal` 파일이 남아 있다면 그것도 함께 복사합니다. 원본 PDF 폴더·렌더링 폴더·Excel 폴더 전체를 같은 백업 폴더에 복사합니다. 따로 내려받은 Excel도 필요하면 함께 보관합니다. 기존 백업을 덮어쓰지 않습니다.
3. 현재 사용한 앱 버전(커밋 또는 받은 날짜), 위 실제 경로와 폴더 대응을 백업 메모에 기록합니다. 외부 설정이 있다면 Git 밖의 접근 제한된 별도 위치에 보관합니다. 비밀을 공개 백업이나 PR에 넣지 않습니다.
4. 복사 완료 후 DB와 파일 개수·용량을 확인합니다. 백업은 자동 생성되지 않으며 실행기가 삭제·초기화하지 않습니다.

## 복구: 원본을 덮어쓰지 않는 확인 절차

1. 모든 서버를 정상 종료합니다. 현재 데이터도 위 방식으로 **별도 백업**합니다. 복구 과정에서 기존 DB나 PDF를 삭제하거나 덮어쓰지 않습니다.
2. 백업 전체를 **새 빈 복구 폴더**에 복사합니다. 사용했던 동일 앱 버전을 준비합니다. 별도 UTF-8 설정 파일에서 DB·원본·렌더링·Excel 경로 네 개를 이 복사본의 절대 경로로 지정합니다. Windows 경로는 `C:/...`처럼 슬래시를 사용하면 설정하기 쉽습니다.
3. 기존 `TAKEOFF_*` 환경변수가 복구 설정을 덮어쓰지 않는지 확인합니다. 실행기에서 외부 설정을 선택해 시작하고 **실제 저장 위치**가 복구 폴더인지 먼저 확인합니다. 다르다면 즉시 정상 종료하고 설정을 바로잡습니다.
4. 기존 프로젝트·PDF·수량·계산식·검수 상태와 Excel을 확인합니다. 확인 전 원본 데이터 폴더를 교체하지 않습니다. 문제가 있으면 종료하고 원본 설정으로 돌아가면 됩니다.

예시(실제 경로로 바꾸고 Git 밖에 저장):

```dotenv
TAKEOFF_DATABASE_URL=sqlite:///C:/Takeoff Recovery/backup/takeoff_assistant.db
TAKEOFF_UPLOADS_DIR=C:/Takeoff Recovery/backup/uploads
TAKEOFF_RENDERED_PAGES_DIR=C:/Takeoff Recovery/backup/rendered
TAKEOFF_EXPORTS_DIR=C:/Takeoff Recovery/backup/exports
```

## 시작 실패·복구 안내

| 표시 | 다음 조치 |
| --- | --- |
| Python 가상환경 없음 | Python 3.11 설치와 README의 가상환경·의존성 준비를 완료합니다. 이미 만든 가상환경을 임의 삭제하지 않습니다. |
| Node.js/웹 의존성 없음 | Node.js 24 설치와 `npm.cmd --prefix apps/web ci`를 최초 준비 담당자가 실행합니다. |
| API 의존성 없음 | README의 해시 lock 설치와 editable API 설치를 완료합니다. |
| 8000/5173 포트 사용 중 | 다른 실행기나 개발 서버의 창을 찾아 그 프로그램에서 정상 종료합니다. 해당 프로그램을 유지해야 한다면 이 실행기를 동시에 사용하지 않습니다. 포트 소유 프로세스를 강제 종료하지 않습니다. |
| 이미 실행 중 | 같은 폴더의 기존 실행기 창을 사용합니다. 실행기를 두 번 열어도 기존 서버를 종료하거나 새 서버를 만들지 않습니다. |
| API/웹 시작 실패·시간 초과 | 시작한 서버가 정리될 때까지 기다립니다. 저장 경로의 쓰기 권한·디스크 여유, 포트, 설치를 확인한 뒤 **시작**으로 재시도합니다. |
| 실행 제어/안전 장치 실패 | 자식 서버를 시작하기 전에 중단합니다. Windows에서 직접 실행해 보고 계속 실패하면 담당자에게 알립니다. 보안 정책을 우회하지 않습니다. |

개발자 진단은 [COMMANDS](COMMANDS.md)의 `dev-api`, `dev-web`을 각각 실행해 오류를 확인합니다. 실행기는 비밀 노출을 막기 위해 원본 서버 로그나 외부 설정 내용을 표시·저장하지 않습니다. 진단 시 환경파일·키·업무 자료가 포함된 출력은 공유하지 마세요.

## 프로세스 소유권과 검증 범위

GUI와 브라우저는 서버 Job 밖에 있습니다. 별도 supervisor가 Windows kill-on-close Job에 들어간 **후에** API와 직접 Vite Node 프로세스를 시작합니다. 모든 자식(예: esbuild)도 Job에 속합니다. 종료는 이번 실행의 `Popen` 핸들과 stdin만 사용하며 PID 파일이나 오래된 PID, 포트 번호로 프로세스를 찾아 죽이지 않습니다. GUI가 비정상 종료되면 stdin EOF로 supervisor가 정리하고, supervisor가 비정상 종료되면 OS가 Job을 닫아 자손을 회수합니다. Job 할당 실패 시 서버는 시작하지 않습니다.

이 도구는 준비된 Windows의 개인 로컬 개발 서버 실행을 위한 것입니다. 설치 패키징·서비스 등록·다중 사용자·클라우드 배포는 포함하지 않습니다. 합성 데이터의 실행·종료 확인은 실제 사용자의 실무 검수나 정확도 검증을 뜻하지 않습니다.
