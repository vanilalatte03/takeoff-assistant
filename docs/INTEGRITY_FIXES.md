# 산출 무결성: F01~F07

이 문서는 2026-10-22 공개 적합성 감사에서 확인한 F01~F07의 저장 계약과 회귀 검증 범위를 정의한다. 자동 치수선 판독, OCR, 회전 PDF, Excel 문자열 수식 방지, 의존성 보안 갱신은 이 변경의 범위가 아니다.

## 저장 계약

| 항목 | 보장해야 하는 동작 |
| --- | --- |
| F01 합계 | `REJECTED` 수량은 Summary에 합산하지 않는다. Details에는 검수 이력으로 남길 수 있다. |
| F02 재계산 | 계산 API 입력은 `coordinates_json.calculation_inputs`에 보존하고, 화면 재선택 때 치수·계산 방식·공제를 복원한다. 이전 데이터는 `deductions_json.items`와 치수 선택 근거를 사용한다. |
| F03 페이지 변경 | 파일·페이지가 바뀌면 축척·선택점·계산 결과·치수 후보 상태를 초기화한다. 이전 페이지의 늦은 응답을 현재 페이지에 적용하지 않는다. |
| F04 단위 | 면적은 `m2`, 길이는 `m`, 개수는 `EA`다. 서버에서도 산출 타입과 단위를 검증하고, 잘못된 치수·공제를 거부한다. |
| F05 소속 | 수동 생성한 RoomFinish도 PDF 소속을 보존한다. 다른 프로젝트·PDF의 산출을 섞어 병합하지 않는다. |
| F06 검수 상태 | 확정 행은 읽기 전용이다. 사용자가 `status: DRAFT`만 보내 확정을 취소한 뒤 수정한다. 거절 행은 계산·PATCH로 되살리지 않으며 거절한 방에서 새 후보를 생성하지 않는다. |
| F07 근거 | 출처 도면을 합집합으로 보존하고, 새 측정 저장에서 기존 메모·치수 선택 근거를 유지한다. 새 측정과 무관한 이전 계산 입력·공제를 남기지 않는다. 병합은 원본의 근거를 보존하고 미계산 항목을 숨기지 않는다. |

`calculation_inputs`는 서버가 계산에 사용한 입력 스냅샷이다. 사용자 PATCH로 임의의 계산 입력을 주입하여 복원 근거로 삼지 않는다. 계산 수량·수식·단위·타입을 직접 바꾸면 오래된 계산 입력도 무효화한다. 변경이 없는 메타데이터 저장은 계산 근거를 지우지 않는다.

계산 화면은 원본 입력 스냅샷의 공제를 우선 복원한다. 표시용으로 반올림한 기존 공제 JSON을 우선하면 소수 공제가 재저장 때 달라질 수 있다. 새 수동 측정은 `active_input_source: manual_geometry`로 표시하고 현재 수량을 CUSTOM 입력으로 복원한다. 새 치수 후보를 선택하면 `active_input_source: dimension_assist`로 바꾸어 보존된 옛 도형과 현재 선택을 구분한다. 두 경로 모두 예전 근거는 보존하지만 현재 입력으로 잘못 재사용하지 않는다.

## 기존 SQLite 데이터

RoomFinish의 PDF 소속 컬럼은 추가 방식으로 적용한다. 원본 업무 DB를 삭제하거나 새로 생성하지 않는다. 기존 drawing sheet에서 명확하게 확인되는 소속만 채운다. sheet도 소속도 없는 옛 수동 행은 임의의 PDF에 붙이지 않고 미배정 상태로 유지하며, 파일별 목록과 export에는 포함하지 않는다.

운영 데이터에 적용하기 전 서버를 종료하고 SQLite DB와 업로드 디렉터리를 별도 위치에 복사한다. 검증은 합성 DB에서 수행하며 실제 업무 DB를 테스트 fixture로 사용하지 않는다.

## 회귀 검증

다음은 개별 CRUD 성공 여부와 별도로 확인할 연결 시나리오다.

1. 수량 10과 6을 병합한 뒤 Excel을 내보내면 Summary와 활성 Review 수량이 16이다.
2. `4.2 * 4.6 - 1.89 = 17.43` 계산을 저장하고 행을 다시 선택해 재저장해도 공제가 유지된다.
3. 페이지 0에서 측정한 뒤 페이지 1로 이동하면 기존 축척과 결과를 저장할 수 없다.
4. 길이 결과를 바닥 면적에 저장하거나 음수 치수·잘못된 단위를 API로 보내면 거부된다.
5. PDF1에 수동 생성한 방이 PDF2에 나타나지 않고, 프로젝트/PDF가 다른 산출의 병합도 거부된다.
6. CONFIRMED를 바로 수정·계산·거절하는 경로와 REJECTED를 되살리는 경로가 차단된다. 명시적으로 확정을 취소하면 편집할 수 있다.
7. 다른 도면에서 측정하면 기존 출처와 새 도면이 함께 남고, 메모·치수 후보 근거가 보존된다. 새 수동 측정으로 바뀐 결과에 옛 공제가 남지 않는다.
8. 미계산 원본이 있는 병합을 거부하고, 정상 병합은 원본 ID·출처·좌표·공제를 추적할 수 있다.
9. 이전 SQLite schema를 반복 초기화해도 데이터와 명확한 소속이 유지되고, 불명확한 소속을 추측하지 않는다.
10. 과거 잘못된 단위로 확정한 행도 명시적으로 확정을 취소한 뒤 정정할 수 있다. RoomFinish도 확정 취소는 상태만 변경하는 별도 버튼으로 수행한다.

## 실행

백엔드는 `docs/COMMANDS.md`의 pytest 명령을 사용한다. 프론트엔드는 `apps/web`에서 `npm run test`와 `npm run build`를 실행한다. 새 UI 회귀는 테스트 DOM에서 실제 컴포넌트의 선택·클릭·저장 payload를 검증한다. 브라우저와 실무 도면의 전체 E2E 완료를 의미하지 않는다.

감사의 F09(새 PyMuPDF 조합에서 Windows 손상 PDF 정리 실패)는 별도 이슈다. 이번 변경의 API 회귀 검증에서 사용한 의존성 조합을 PR 검증 결과에 명시한다.
