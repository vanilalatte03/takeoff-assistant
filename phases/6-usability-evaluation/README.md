# 6차: 실사용 흐름과 AI 효과 검증

## 목적과 기준

기능 수보다 사용자가 도면을 올리고 근거를 검토해 수량을 계산하고 Excel을 받는 한 과제의 완주를 우선한다. AI가 추가로 도움이 되는지는 **기존 수작업 / 로컬 검색·계산 보조 / AI 보조**를 구분해 평가한다. 다단계 에이전트는 선택 실험이며 이번 필수 구현에 포함하지 않는다.

기준 브랜치는 main이다. PR #11~#15의 탐색·계산·판독·평가 기록 기능을 재사용한다. [요구사항 감사](../../docs/AI_ASSIST_AUDIT.md), [기존 진행 기록](../../docs/AI_ASSIST_PROGRESS.md), [전체 운영 규칙](../README.md)을 먼저 확인한다. 단계 상태는 [index.json](index.json)에 기록한다.

기본 구현 순서는 0 → 1 → 2 → 3 → 4 → 5 → 6이다. 실무자가 참여할 수 있으면 최소 작업 흐름 3·4를 먼저 준비해 작은 과제 하나를 관찰할 수 있다. 1의 실제 정답 검수는 7까지 열어두며, 합성 사례의 명시적 정답으로 2·5의 개발 검증을 진행할 수 있다. 검색 관련 도면 정답과 산출 수량 정답은 별개로 관리한다.

## 최종 인수 기준과 외부 게이트

- 검수되지 않은 업무 행은 정답 평가에서 제외되고 제외 이유가 기록된다.
- 검색·Vision은 같은 자료와 설정으로 재현 가능하며 합성 성능을 실무 성능으로 일반화하지 않는다.
- 처음 사용하는 사람이 화면 안내를 따라 합성 도면의 천장 초안을 작성하고 원본·단위·공제를 검수해 Excel을 받을 수 있다. 실제 사용자 수행 여부는 7에서 확인한다.
- 준비된 Windows 환경에서 명령어 직접 입력 없이 실행·종료하고, 데이터 위치·백업·복구 안내를 확인할 수 있다.
- 계산식·수량·단위·출처·좌표·공제·검수 상태를 보존하고, 재실행은 확정/제외 데이터를 훼손하지 않는다.
- 수작업·로컬 파일럿에는 실제 도면 이용 권한, 실무자가 승인한 정답, 사용자 관찰이 필요하다. AI/Vision에 업무 도면을 외부 전송할 때만 별도 전송 권한을 확인한다. 0~6이 완료돼도 7과 R-04/11/12가 자동 완료되지 않는다.
- 실제 수행 결과에서 재검토·수정·Excel 확인까지 포함한 시간과 오류·개입·채택 여부를 비교하고, 발견한 결함은 별도 PR로 수정한다.

## 선택 실험 H

2의 기준선과 7의 관찰에서 단일 검색으로 해결하지 못하는 실패가 확인될 때 제한적 다단계 탐색의 필요성을 판단한다. 진행한다면 별도 phase/PR에서 호출·재탐색·비용 상한, 근거 없는 결과의 확인 요청, 수량 확정 권한 제외를 정의한다. 도면 원문을 모델에 전달하면 전송 범위가 늘어나므로 데이터 최소화와 명시적 전송 승인 정책을 먼저 정한다. 성공 기준은 도구 호출 횟수가 아니라 기존 검색 대비 탐색 성공률 또는 전체 작업시간의 개선이다. 근거가 없으면 실험 보류 사유를 기록한다.
